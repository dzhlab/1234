## 2. Безопасность

### 2.1. Аутентификация

**Требования:**
- ✅ Обязательная аутентификация для всех действий (кроме просмотра публичных результатов)
- ✅ Хэширование паролей: bcrypt (cost factor: 12)
- ✅ JWT токены для API (срок действия: 1 час для access, 7 дней для refresh)
- ✅ Двухфакторная аутентификация (2FA) — опционально для администраторов

**Политика паролей:**
- Минимальная длина: 8 символов
- Требования: минимум 1 заглавная буква, 1 цифра, 1 специальный символ
- Блокировка учётной записи после 5 неудачных попыток входа

### 2.2. Авторизация

**Модель:** Role-Based Access Control (RBAC)

**Роли:**
1. **Admin** — полный доступ
2. **Organizer** — управление соревнованиями
3. **Chief Judge** — контроль судейства
4. **Secretary** — обработка оценок
5. **Judge** — выставление оценок
6. **Viewer** — только чтение

**Матрица прав доступа:**

| Действие | Admin | Organizer | Chief Judge | Secretary | Judge | Viewer |
|----------|-------|-----------|-------------|-----------|-------|--------|
| Создать соревнование | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ |
| Удалить соревнование | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ |
| Редактировать настройки | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ |
| Назначить судей | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ |
| Выставить оценку | ✅ | ❌ | ✅ | ❌ | ✅ | ❌ |
| Утвердить оценку | ✅ | ❌ | ✅ | ✅ | ❌ | ❌ |
| Просмотреть результаты | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| Экспорт протоколов | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ |

### 2.3. Защита данных

**Шифрование:**
- ✅ **В транзите:** TLS 1.3 (HTTPS, WSS)
- ✅ **В покое:** Шифрование диска (AES-256)
- ✅ **Резервные копии:** Шифрование GPG

**Защита от атак:**
- ✅ **SQL Injection:** Параметризованные запросы (Prepared Statements)
- ✅ **XSS:** Санитизация входных данных, Content Security Policy (CSP)
- ✅ **CSRF:** CSRF токены для всех форм
- ✅ **DDoS:** Rate limiting, WAF (Web Application Firewall)
- ✅ **Brute Force:** Блокировка после 5 неудачных попыток

### 2.4. Аудит безопасности

**Логирование:**
- Все входы/выходы пользователей
- Все изменения данных (INSERT, UPDATE, DELETE)
- Все попытки несанкционированного доступа
- Хранение логов: минимум 1 год

**Мониторинг:**
- Автоматическое оповещение о подозрительной активности
- Еженедельные отчёты о безопасности

## 3. Надёжность и доступность

### 3.1. Целевые показатели

**SLA (Service Level Agreement):**
- **Доступность (Uptime):** 99.5% (допустимо 3.6 часа простоя в месяц)
- **MTBF (Mean Time Between Failures):** > 720 часов (30 дней)
- **MTTR (Mean Time To Repair):** < 2 часа

### 3.2. Отказоустойчивость

**Стратегии:**
- ✅ **Репликация базы данных:** Master-Slave (автоматический failover)
- ✅ **Резервные серверы:** Hot standby для критических компонентов
- ✅ **Graceful degradation:** Система продолжает работать в ограниченном режиме при отказе части компонентов

**Примеры сценариев:**
- **Отказ БД Master:** Автоматическое переключение на Replica (<30 сек)
- **Отказ WebSocket сервера:** Переключение на Long Polling
- **Отказ интернета (локальная сеть):** Локальный режим работы

### 3.3. Восстановление после сбоев

**RPO (Recovery Point Objective):** < 5 минут (максимальная потеря данных)
**RTO (Recovery Time Objective):** < 30 минут (время восстановления)

**План восстановления:**
1. Автоматическое резервное копирование каждые 6 часов
2. Инкрементальные бэкапы каждый час
3. Хранение бэкапов: 30 дней онлайн, 1 год офлайн

## 10. Мониторинг и логирование

### 10.1. Мониторинг

**Уровни:**
1. **Инфраструктура:** CPU, RAM, Disk, Network
2. **Приложение:** API response time, WebSocket connections
3. **База данных:** Query performance, Connection pool
4. **Бизнес-метрики:** Количество оценок в минуту, активных судей

**Алерты:**
- ⚠️ Warning: CPU > 70%, Response time > 2 сек
- 🚨 Critical: CPU > 90%, DB недоступна, Error rate > 5%

### 10.2. Логирование

**Уровни логов:**
- `ERROR` — ошибки, требующие немедленного внимания
- `WARN` — предупреждения (например, медленные запросы)
- `INFO` — информационные сообщения (вход пользователя, создание соревнования)
- `DEBUG` — отладочная информация (только в dev-окружении)

**Формат:**
```json
{
  "timestamp": "2025-04-15T10:30:00.123Z",
  "level": "INFO",
  "service": "api-server",
  "user_id": "user-uuid",
  "action": "score_submitted",
  "details": {
    "start_list_id": "startlist-uuid",
    "score_value": 9.450
  }
}
```

**Ротация логов:**
- Ежедневная ротация
- Сжатие старых логов (gzip)
- Хранение: 90 дней
