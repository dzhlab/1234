# Промпт для Claude Code: Улучшение функциональной спецификации

## Задача

Прочитай файл `ФУНКЦИОНАЛЬНАЯ_СПЕЦИФИКАЦИЯ__2_.md` и выполни комплексный анализ, улучшение, расширение и структурирование документа.

---

## Шаг 1: Анализ текущего состояния

Прочитай весь документ и создай краткий отчёт:

```bash
# Сначала прочитай файл
cat ФУНКЦИОНАЛЬНАЯ_СПЕЦИФИКАЦИЯ__2_.md
```

После прочтения сформируй:
1. **Общую структуру** — какие разделы есть
2. **Пробелы** — что отсутствует или недостаточно раскрыто
3. **Несоответствия** — противоречия между разделами
4. **Качество** — оценка полноты каждого раздела (1-10)

---

## Шаг 2: Улучшение документа

### 2.1. Структурные улучшения

Добавь или улучши следующие разделы:

- [ ] **Глоссарий терминов** — единообразие терминологии (FIG, D-score, E-score и т.д.)
- [ ] **Нефункциональные требования** — производительность, безопасность, доступность, масштабируемость
- [ ] **Требования к интеграциям** — API для внешних систем, экспорт данных
- [ ] **Пользовательские сценарии (User Stories)** — формат: "Как [роль], я хочу [действие], чтобы [результат]"
- [ ] **Диаграммы** — добавь Mermaid-диаграммы для:
  - Архитектура системы
  - Последовательности (sequence diagrams) для ключевых процессов
  - ER-диаграмма базы данных
  - Диаграмма состояний выступления

### 2.2. Расширение функциональных требований

Проверь и дополни:

- [ ] **Обработка ошибок** — как система ведёт себя при сбоях
- [ ] **Граничные случаи** — что если судья отключился, что если ничья, и т.д.
- [ ] **Аудит и логирование** — отслеживание всех действий
- [ ] **Резервное копирование** — стратегия бэкапов
- [ ] **Оффлайн-режим** — детальное описание работы без интернета
- [ ] **Мобильная версия** — адаптация интерфейсов

### 2.3. Улучшение форматирования

- [ ] Унифицируй стиль всех таблиц
- [ ] Добавь якорные ссылки ко всем разделам
- [ ] Исправь битые внутренние ссылки
- [ ] Добавь номера версий для каждого раздела

## Шаг 4: Приоритетные задачи

### Высокий приоритет:
1. **Добавь полную ER-диаграмму** базы данных в формате Mermaid
2. **Опиши REST API** для всех сущностей (спортсмены, судьи, оценки, соревнования)
3. **Добавь раздел безопасности** — аутентификация, авторизация, шифрование
4. **Расширь раздел "Роли и доступы"** — матрица прав доступа

### Средний приоритет:
5. Добавь **acceptance criteria** к каждому функциональному требованию
6. Создай **карту экранов** (sitemap) всей системы
7. Опиши **алгоритм расчёта итоговых оценок** в псевдокоде
8. Добавь **примеры JSON** для всех API-запросов

### Низкий приоритет:
9. Переведи ключевые разделы на английский
10. Добавь раздел с часто задаваемыми вопросами (FAQ)

## Шаг 5: Формат вывода

После всех улучшений создай:

1. **SUMMARY.md** — краткое резюме всех внесённых изменений
2. **TODO.md** — список того, что ещё нужно доработать
3. Обнови **оглавление** в основном документе

## Технические требования к улучшенному документу

- Формат: Markdown (CommonMark)
- Диаграммы: Mermaid
- Код: с подсветкой синтаксиса
- Таблицы: выровнены, с заголовками
- Ссылки: все рабочие (проверить!)
- Нумерация: иерархическая (1.1, 1.2, 1.2.1...)

## Пример улучшения раздела

**До:**
```markdown
### 5.1. Создание судейской бригады
Создание бригады для события.
```

**После:**
```markdown
### 5.1. Создание судейской бригады

#### 5.1.1. Описание
Модуль позволяет формировать судейские бригады в соответствии с правилами FIG 2025-2028.

#### 5.1.2. Предусловия
- Соревнование создано и активно
- Пользователь имеет роль "Главный секретарь" или "Администратор"

#### 5.1.3. Основной сценарий
1. Пользователь открывает раздел "Судейские бригады"
2. Нажимает "Создать бригаду"
3. Выбирает тип бригады (D, E, A)
4. Назначает судей из списка
5. Система валидирует состав
6. Бригада сохраняется

#### 5.1.4. Альтернативные сценарии
- **A1**: Недостаточно судей — система показывает предупреждение
- **A2**: Конфликт расписания — система предлагает замену

#### 5.1.5. Acceptance Criteria
- [ ] Бригада содержит минимум 2 судьи
- [ ] Нельзя назначить одного судью в две бригады одновременно
- [ ] История изменений сохраняется

#### 5.1.6. Связанные требования
- [5.2. Назначение судей на бригаду](#52-назначение-судей-на-бригаду)
- [7.3. Права роли "Главный секретарь"](#73-права-роли-главный-секретарь)
```
